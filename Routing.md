# Routing

```
https://example.com:80/path/to/page.html?html?=key1=value&key2=value2#location
|Scheme|Domain Name|port|------path------|--------Query Sting---------|--Hash--|
```
- Scheme: indicates protocol used to request the resouce
- Domain Name: provides server location(human readable alternative to IP)
- Path: indicate specific resource on server
- Query String: way to pass argument to server
- Hash(Anchor sort or bookmark) : used to hash to scroll the page to a specific location (only used by client not server)

  - we click link to update the path nad it makes a request to render the response
  - when page loades we start from empty page
  - >ideally we want to chnage the page wothout having to reload all the JS

  ## Single page App (SPA) (CSR)
  - complete client side rendered application
  - server send a single index.html and JS generates the entire application once the papge has loaded on the client
  - the page is boradly empty utill the client loads and execute the JS(loading satte is required) reloading the borwser causes full reload
  - implemented by React Router

  ## Server Side Rendering (SSR)
  - aims to pre-render the UI generated by a JS Framework on the server
  - rather than sending an empty HTML page to be populated on the client the JS is run on server and generate HTML is then sent to client
  - user dont have to wait for all the jS to load before the initial view is rendered on the screen

  ### notable downsides to this approach
  - need knowledge of server side concepts, another framework to learn and added complexity
